# Logging Contract — aimedia 📜

> [!abstract] Назначение документа
> Этот документ фиксирует контракт диагностических событий aimedia: разрешённые
> поля, каналы вывода, редакцию секретов, корреляцию и retention. Он описывает
> **реализованное** на E01 (модуль `aimedia.logging`, события
> `app_started`/`config_loaded`/`command_finished`) и целевые правила для
> последующих этапов.

## Три разных хранилища сведений 🗃️

| Хранилище | Отвечает на вопрос | Где живёт | Retention |
|---|---|---|---|
| History | Что отправлялось и что получилось | SQLite в data-root | Жизнь пользовательской истории |
| Diagnostics | Почему произошёл переход, отказ, сколько заняло | stderr и лог-файл в data-root | Ограниченная локальная ротация |
| QA evidence | Какими тестами проверялась программа | `artifacts/quality/<sha>/` вне Git | Артефакт CI/release |

История prompt не дублируется целиком в log, а runtime log не заменяет отчёт
pytest. Diagnostics не являются источником бизнес-данных и не восстанавливают Job.

## Каналы вывода 📡

- **stdout** принадлежит пользовательскому результату. В режиме `--json` stdout
  содержит ровно один JSON-документ; диагностические записи туда не попадают.
- **stderr** — диагностика, предупреждения и прогресс.
- **Лог-файл** (будущие этапы) — тот же формат записей, что и в stderr, с локальной
  ротацией. Автоматическая отправка telemetry в v0.1 не вводится.
- Обычная справка и `version` без `--json` не производят диагностического шума:
  диагностика настраивается только для команд, которые её действительно пишут.

## Формат записи 🧾

Каждое событие — один JSON-объект в строке. Разрешённые поля:

| Поле | Обязательность | Смысл |
|---|---|---|
| `timestamp_utc` | да | UTC-время в ISO-8601 |
| `level` | да | DEBUG/INFO/WARNING/ERROR/CRITICAL |
| `event` | да | Имя события (`app_started`, `config_loaded`, …) |
| `component` | да | Подсистема-источник (`cli`, `provider`, …) |
| `command` | когда есть | Команда или её путь |
| `job_id` | когда есть | Локальный ID Job |
| `provider` | когда есть | Имя provider |
| `remote_operation` | когда есть | Тип удалённой операции |
| `remote_job_id` | когда есть | Безопасный ID удалённой операции |
| `duration_ms` | когда есть | Длительность в миллисекундах |
| `details` | когда есть | Произвольные структурированные сведения |

Список полей реализован в `aimedia.logging.EVENT_FIELDS`; новые поля добавляются
вместе с обновлением этой таблицы.

## События E01 🚀

| Событие | Когда | Содержимое |
|---|---|---|
| `app_started` | старт команды | версия и нормализованный путь команды (без значений опций) |
| `config_loaded` | после разрешения настроек | **только** имена источников: `cli`/`config`/`env`/`default` |
| `command_finished` | завершение команды | итоговый `exit_code` и `duration_ms` |

`config_loaded` намеренно не содержит значений настроек: секретов, путей и уровней
там нет, потому что логируется только то, какие источники участвовали.

## Корреляция 🧵

Корреляция хранится в `contextvars` (`aimedia.logging.correlation`). Это не даёт
контексту одного batch-Job перетечь в соседнюю coroutine или поток: каждый Job
получает собственный `job_id`. Global-состояние одного Job не должно становиться
корреляцией соседнего.

## Redaction 🔐

Удаляются из всех каналов (запись, вложенные `details`, трассировка исключения):

- API keys и любые поля, чьё имя содержит `api_key`, `token`, `secret`,
  `password`, `authorization`, `bearer`, `cookie`, `credential`;
- Authorization headers, cookies, URL credentials, signed query-токены;
- base64 payloads и полный provider request body;
- чувствительные данные, повторённые сервером внутри `message` или nested metadata.

Известные значения секретов дополнительно подставляются как цели редакции
(`EventLogger.secrets`), поэтому даже случайная подстрока в тексте удаляется.
Canary-тест намеренно помещает тестовый секрет в сообщение, вложенные details и
форматируемое исключение и проверяет все каналы вывода.

Редакция покрывает и stdlib-логирование с `exc_info`: фильтр
(`aimedia.logging.RedactingFilter`) заменяет `record.exc_info`/`record.stack_info`
уже отредактированным текстом **до** вызова `Formatter`. `Logger.exception()` не
обходит фильтр: трассировка строится из отредактированного `exc_text`, а вся
цепочка `__cause__`/`__context__` и аргументы исключений проходят один проход
`redact_text`.

Сам plaintext prompt, который пользователь сознательно сохраняет в локальной
истории, остаётся продуктовой функцией; это не разрешение копировать его в
общедоступный CI-лог.

## Retention и доступ 📦

- Локальный лог-файл ограничивается ротацией; retention задаётся вместе с
  реализацией файлового обработчика.
- Retention reports и доступ определяются отдельно от истории пользователя.
- QA evidence хранится по SHA в `artifacts/quality/<sha>/` и не содержит секретов.
