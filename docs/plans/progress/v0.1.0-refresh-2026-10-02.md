# v0.1.0 — разрешённый docs-only refresh, 2026-10-02

## Решение и границы

Владелец явно разрешил: «коммить пуш тег релиза смещаем тоже обновляем сборку UV
тул у меня». Это разовое именованное исключение к обычной immutable policy:
интегратор переносит существующий `v0.1.0` на актуальный docs commit, заменяет
assets того же release и обновляет обычный личный uv tool. Версия остаётся `0.1.0`.
Запись фиксирует разрешение и порядок, **не заявляет выполненную публикацию**.

Исходная публикация: tag object `77079872c76c7bf198339c31de9c47208c58d742`, peeled
commit `f7fb04e6768aaf1c04c575166e5b73a5e4e95473`. Он остаётся первоначально
принятым runtime. Exact new source commit/tag provenance записываются после
commit в публичные release notes и `release-manifest.json`, а не угадываются в
этом предкоммитном документе.

Объём — README, release workflow/навигация и эта запись решения. После первой
сборки отдельно разрешено узкое исправление `.gitignore`: `!/.env.example` вместо
глобального исключения, чтобы sdist не подхватывал templates из `.pi/` и корневого
`artifacts/`. Первая попытка сохраняется; разрешена одна корректирующая offline
сборка и проверка members, без ручной перепаковки архивов. Runtime, tests,
`uv.lock`, `pyproject.toml`, CI, спецификации `01`–`09`, лицензии и содержимое
навыков не меняются. Три root-пакета/четыре `SKILL.md` доступны в Git source/tag
и sdist `docs/skills/`; wheel и установленный tool не получают навыки, новые
CLI-команды или автоматическую регистрацию в Pi.

## Подготовка и публикация

1. Один Git diff подтверждает неизменность runtime/tests/lock/pyproject относительно
   f7. Минимальные новые проверки — docs links/YAML/whitespace, одна offline сборка
   wheel/sdist из existing uv cache и проверка archive members. Не нужны повторные
   full pytest/OS gates/live/CI-watch, свежие envs, sync или установка dependencies.
   Секреты удаляются из child env по именам с учётом alias; `.env` не загружается.
2. Старые assets/evidence сохраняются без перезаписи в
   `artifacts/archive/v0.1.0/aimedia-publication-v010/`. Новая подготовка — отдельно
   в ignored `artifacts/quality/release-refresh-20261002/`. Offline build failure
   останавливает подготовку, не разрешает скачивание backend.
3. После независимого review интегратор коммитит те же docs bytes, публикует main,
   переносит annotated tag и финализирует metadata actual commit/old-new tag
   provenance. Manifest связывает новые wheel/sdist/constraints/verification;
   `SHA256SUMS` генерируется **после** stamp metadata. Templates не публикуются.
4. Заменяются ровно шесть assets: `aimedia-0.1.0-py3-none-any.whl`,
   `aimedia-0.1.0.tar.gz`, `runtime-constraints.txt`, `verification.json`,
   `release-manifest.json`, `SHA256SUMS`. Constraints повторно используются
   побайтно из исходной приёмки, поскольку dependencies/lock неизменны.
5. После публикации обычный tool переустанавливается по тому же тегу с
   `--reinstall-package aimedia` и актуальными constraints; соседние tools и
   глобальный cache не трогаются. Installed `direct_url.json` сверяется с новым
   peeled commit, а не только с banner `0.1.0`. Пользовательские данные/ключи/БД
   не используются для проверок, новых paid calls нет.

Команды/правила — [RELEASE.verified-tool](../../../instructions/RELEASE.verified-tool.instructions.md).
