## Локальная авторизация

По явному разрешению владельца существующий ключ помещён в пользовательское
окружение Windows `POLZA_API_KEY`, не в TOML/argv/Git/evidence. Readback совпал,
отправлено уведомление Windows об изменении окружения. Auth-only
`GET /api/v1/key` вернул HTTP200; тело ответа и значение ключа не сохранялись.
Установка пакета другим пользователем ключ не переносит. Для обычного запуска
после изменения окружения откройте новый терминал. Генерация платная и здесь
не выполнялась; наличие ключа не доказывает живую поддержку всех режимов моделей.

## Публикация и установка по тегу

До переноса: annotated object `dfb07a67e75a7e3b92685418d5670f54dcf086f5` →
`de6cee2a7d2a718984304852366599e7a0b17f53`. Прежние notes/шесть assets сохраняются
в отдельном rollback-каталоге `artifacts/quality/gpt25-publication-20261004/`.
Новая сборка — из tracked source и owned docs, без чужих untracked/state files.
Поставка относительно прежнего тега меняет runtime/catalog; только последний
документационный слой поверх implementation commit является docs-only.

Интегратор после review создаёт docs commit, публикует main обычным fast-forward,
переносит annotated tag с exact old-tag lease, заменяет wheel/sdist/constraints/
verification/manifest/SHA256SUMS и notes. Metadata содержит actual final source
commit и новую tag provenance; checksum-файл создаётся последним.
Constraints переиспользуются без изменения, поскольку dependencies не менялись.

Обычный личный uv tool переустанавливается **по публичному тегу**, не оставляется
на локальном wheel: `--reinstall-package aimedia`, Python3.12, release constraints.
Installed VCS commit должен совпасть с новым peeled tag; проверяются модели/aliases/
help вне checkout. Новых ключей, пользовательской БД и платных Jobs не создаётся.
Exact final identity задаёт публичный `release-manifest.json`, результаты remote
операций и установки — отдельные receipts. Эта запись фиксирует scope/порядок
и уже выполненные implementation checks, не обещает завершённый remote push заранее.
