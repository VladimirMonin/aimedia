Нормативные источники: [01 — Product Scope](01-product-scope.md),
[README — карта плана](README.md). Решения по развилкам —
[decisions/implementation-baseline.md](decisions/implementation-baseline.md),

## (a) Обязательная функциональность v0.1

Обязательный объём собран из обязательной таблицы `01` (Product Scope, раздел
«Состав первой версии») и уточнений baseline E00. Всё перечисленное закрывается
проверками из [verification-matrix.md](verification-matrix.md).

**Продуктовые сценарии**

- Text-to-image и image-to-image.
- Один reference image и несколько reference images в одном запросе.
- Prompt строкой из CLI и из файла; несколько prompt-файлов.
- Один запрошенный output одного Job/request. Несколько выходных изображений
  одного submit **отложены прямым решением владельца CN-05**; это не несколько
  входных reference images, которые остаются обязательными.
- Batch генерация: каждый независимый item — **отдельный** Job;
  ограниченная concurrency (`--concurrency`) и partial-batch outcome.
- Выбор модели и явный выбор provider; валидация model capabilities.
- Основной provider — Polza.

**Входы и формат результата**

- Пользовательская output directory (`--out`).
- Локальные конечные форматы PNG/JPEG/WebP (`final_format`), alias `jpg → jpeg`.
- Локальная конвертация изображений; локальный WebP ≠ native WebP модели.
- Hash входных файлов (SHA-256 в `inputs.sha256`) — обязательный пункт истории,
  а не «Желательно» из `01`.

**История, стоимость, поиск**

- SQLite history: сохранение prompt, параметров, ссылок и hashes входов, remote
  identifiers (`remote_job_id` и тип операции `operation` в remote ref/snapshot),
  результатов, raw usage, известной фактической стоимости с валютой.
- Восстановление истории после перезапуска: сохранённые `remote_job_id` и
  `operation` (вместе с hashes входов) позволяют проверить историю нового
  соединением/процессом, не угадывая remote endpoint по строке ID.
- Просмотр задания, повтор задания, синхронизация незавершённых заданий.
- **SQLite FTS5 по истории — обязательный пункт** (переведён из «Желательно»;
  закрывается на E09). Это лексический, а не семантический/морфологический поиск.
  Обязательная команда — `aimedia jobs search` с позиционным `query` и `--json`.
  Corpus включает prompts, reference provenance/имена/managed paths/hashes и
  result artifact имена/local paths/hashes/сохранённые metadata; результат — связанные
  Jobs. Это DB-only snapshots, без чтения изображений/legacy-файлов, OCR или embeddings.
  Отсутствие поискового слова в prompt/model не отменяет поиск refs/results.
- **Сводка расходов по отдельным валютам — обязательный пункт** (переведена из
  «Желательно»; закрывается на E09). Валюты не смешиваются; ноль ≠ неизвестная цена.
  Обязательная команда — `aimedia jobs costs` с минимальными опциями `--today` и
  `--month` (границы периода) и `--json`.

**Интерфейс и справка**

- JSON output для важных операций; два согласованных положения глобальных флагов.
- Markdown help system, Atomic docs, Help для моделей (`models show`).
- `--raw` = resolved Markdown без front matter и неразрешённых директив; ANSI нет.

**Надёжность**

- Минимальная cross-process защита от двух Runner одного Job (status-guard +
  короткая транзакция); конкретная схема — до E08.
- Встроенный каталог содержит только проверенные записи.

| Удаление истории | отложено | не входит в v0.1 |
| Универсальные batch manifests | отложено | не входит в v0.1 |
| Публичные maintenance-команды | отложено | не входит в v0.1 |
| Копирование старого Job как нового | желательно, не блокирует | не входит в v0.1 |
| Кэширование скачанных remote файлов | желательно, не блокирует | не входит в v0.1 |
| Фильтрация jobs по модели | желательно, не блокирует | не входит в v0.1 |

## (c) Обязательные CLI-команды (план, не реализация)

Следующий перечень — обязательный объём публичного интерфейса, который предстоит
**реализовать** на E09. Здесь он фиксирует контракт, а не работу программы.

```text
aimedia image generate
aimedia image batch
aimedia jobs recent
aimedia jobs search <query>
aimedia jobs show
aimedia jobs retry
aimedia jobs sync
aimedia jobs costs
aimedia models list
aimedia models show
aimedia providers list
aimedia version
aimedia --help
```

- Команды чтения и версия работают без API key и без сети.
- Минимальные options обязательного поиска и сводки расходов: `jobs search <query>`
  (`--json`) и `jobs costs --today`/`--month` (`--json`). `jobs recent` не получает
  фильтр по модели в v0.1 (см. (b)), но сохраняет `--limit`, `--status` и `--json`.
- Человекочитаемый вывод не является источником данных для JSON mode; контракт
  JSON и exit codes (`0`, `1`, `2`–`9`, `130`) сохраняется для `jobs search` и
  `jobs costs`.
- `providers list` различает наличие adapter, наличие конфигурации и фактическую
  проверку авторизации: «configured» не означает «ключ принят сервером».
- Валидные exit codes: `0`, `1` (internal error), `2`–`9`, `130` (Ctrl+C) —
  см. `04`.

Список подтверждённых моделей на момент E00 **пуст**: ни один remote model ID не
объявлен проверенным. Локальный файл `docs/актуальные модели и цены 28.09.2026.png`

Для каждой модели, добавляемой в каталог, отдельно фиксируются:

- точный **remote model ID** (`remote_model_id`);
- источник сведений о параметрах;
- дата проверки;
- результаты live-сценариев по режимам (text→image, prompt+1 ref, prompt+несколько refs).

Наличие YAML-записи не означает проверенную поддержку. Документированный `4K` не
помечается как испытанный, если выполнялся только `1K`. Минимальная live-приёмка
Polza закрывается на E06/E10.

### CN-01. Долговечные managed-копии reference images (schema v2 + файловый шов) 🗂️

**Что принимается.** Reference images, переданные пользователем в Job, должны
сохраняться как управляемые копии в managed-дереве app data и связываться с Job
(путь, `sha256`, MIME, размер, позиция), а не оставаться только внешними ссылками
на пользовательский файл. После удаления исходника пользователь и агент должны
находить и открывать сохранённую копию по истории Job.

**Migration.** Новые данные оформляются **миграцией v2**. Принятая schema **v1 не
переписывается** и не редактируется задним числом: существующие БД обновляются
вперёд (текущая цепочка — v1 → v2), автоматический destructive downgrade не
обещается (D11).

**Ownership и безопасность (контракт).**

- копия создаётся из **проверенных байтов** (структурная проверка входа, MIME по
  содержимому, `size_bytes` и SHA-256 по тем же байтам), а не по расширению;
- managed-владелец — только managed-дерево app data: no-clobber, отклонение `..`,
  выхода за root и symlink/junction, без записи в пользовательский каталог;
- пользовательские файлы не копируются молча в `--out`, не перезаписываются и не
  удаляются; `--out` остаётся пользовательским выводом результата;
- managed-копии референсов входят в managed-дерево и в манифест quiescent offline
  backup ([`backup-contract.md`](backup-contract.md)); отсутствие копии или
  несовпадение hash/size делает снимок непроверенным, а не «почти полным»;
- негативные сценарии (недоступный исходник, обрезанный файл, конфликт имени,
  симлинк) не создают ложную запись `completed` и не порождают повторный submit.

**Затронутые принятые строки.** `07-storage-history-costs.md` (схема Job/inputs),
`03-domain-model.md` (роли входов/artifact), пункт (a) этого документа «Hash
входных файлов (SHA-256)» и строка истории с `refs`, `README.md` (E04/E07),
[`verification-matrix.md`](verification-matrix.md) (R07),
[`backup-contract.md`](backup-contract.md) (состав managed-дерева).

**Состояние спецификации.** Правка принятой спецификации под `CN-01` сделана
документарно (блокер `B6`): контракт зафиксирован в
[`07-storage-history-costs.md`](07-storage-history-costs.md) (раздел «Managed-копии
reference images»: таблица v2, пути, ownership, порядок до платного POST, отказы,
требуемые проверки), [`03-domain-model.md`](03-domain-model.md)
(`InputRef.managed_path`), [`README.md`](README.md) (E04/E07),
[`verification-matrix.md`](verification-matrix.md) (R07, R18),
[`backup-contract.md`](backup-contract.md) и инструкции
[`PROCESSING.image-artifacts`](../../instructions/PROCESSING.image-artifacts.instructions.md).

Первый принятый code-срез реализовал schema v2/DTO/repository. Отдельный файловый
шов добавляет snapshot bytes одного чтения, no-clobber копии `inputs/`, проверенный
resolve и hook подтверждения всех DB links до выдачи transport request. v1/v2 DDL
и repository не меняются. Ручной backup manifest/restore проверяется на tmp-данных,
не становится runtime feature. **Не реализованы:** полная E07/CLI/D03-композиция,
пользовательская history show/retry/sync интеграция и backup API. Приёмка всего
`CN-01` не пройдена; writer evidence/review статус — [`release-board.md`](release-board.md).

### CN-02. Лексический поиск остаётся, семантический — backlog следующего релиза 🔎

**Что действует без изменений.** Обязательный объём (a) сохраняет **лексический
SQLite FTS5** (`aimedia jobs search`) и фильтры истории; это поиск по словам, а не
семантический и не морфологически полноценный.

**Уточнение (не отмена).** Семантический/векторный поиск (embeddings, sqlite-vec,
hybrid) — отдельный **backlog следующего релиза**, а не расширение FTS5 и не
задача v0.1.0. Строка (b) «sqlite-vec / hybrid / semantic search | позже | после
E11» сохраняется; дополнительно запрещено выдавать FTS5 за семантический поиск и
писать «поиск понимает смысл», пока semantic-режима нет.

**Границы.** Уточнение не блокирует v0.1.0 и не добавляет runtime-зависимостей.

## CN-04. Единая пользовательская поставка E07–E09

Прямое задание владельца объединяет execution, batch/retry/sync, публичный CLI,
FTS5/history/costs и packaged atomic help в один полезный набор с одним review/gate.
Дополнены local `config init/show/validate` и alias `jobs list → recent`; image-only
scope, обязательные negative/security checks и ограничения E10/E11 сохраняются.

Production metadata подтверждены public catalog GET 2026-09-30 (HTTP 200, no auth,
paid POST 0): `qwen/image-2.1` и `google/gemini-3.1-flash-image-preview`, Media
endpoint и параметры. Bindings **experimental / live unverified**, не active:
генерация требует явного model и `--allow-experimental`. Gemini refs ≤8 по Guide
(каталог 14); unit parameter не опубликован и не выдумывается. Exact RUB tiers
хранятся как pricing metadata, не actual billing/будущая гарантия.

В рабочем кандидате реализованы CLI/D03/archive/history/retry/sync и derived FTS5
миграция v3 без правки принятого v1/v2 DDL, backfill только из DB snapshots.
CN-01 API/files seam ранее принят отдельно; пользовательский CLI проверяется в
этом наборе. Backup CLI/GC не добавлены. Реализация/dirty-worktree evidence не
означают frozen SHA, независимую приёмку, live, Linux или опубликованный релиз.

## CN-05. Один результат, все настройки модели и несколько входных референсов

**Прямое решение владельца 2026-10-01.** Несколько выходных изображений одного
запроса отложены; прежняя трактовка multi-output как обязательного E06/E10 gate
и NO WAIVER отменена. Это изменение объёма, не утверждение о работе provider.
Исходные 01–09 сохраняются как история; при конфликте действует CN-05.

Обязательны генерация **одного изображения**, все документированные параметры
подключённого модельного/provider binding и генерация **по нескольким входным
изображениям + промпт**. Для GPT-5.4 Image 2 с MIE нельзя сохранять прежнее
искусственное ограничение только 1K/text-only: включаются документированные
разрешения, пропорции и references, с явной валидацией допустимых сочетаний.
Параметры других upstreams не приписываются MIE; неподдерживаемые generic поля
не выдумываются. Документированные настройки не выдаются за live-проверенные.
