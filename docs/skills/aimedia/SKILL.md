# aimedia

Работай через установленную команду `aimedia`; checkout не нужен.
Этот файл самодостаточен. Не устанавливай CLI/зависимости и не меняй глобальные
настройки без отдельной задачи. Пользовательские материалы и outputs сохраняй
**вне папки навыка**.

## Узнай актуальный интерфейс и выбери историю

```text
aimedia version --json
aimedia --help
aimedia help --json
aimedia help image.generate --raw
aimedia models list --json
```

Текущие executable version, `--help`, `help <topic> --raw` и
`models show <model-id> --json` — источник фактических команд, параметров,
лимитов и defaults. Не копируй сюда весь каталог и не приписывай YAML-записи
гарантию живой доступности. Темы для деталей: `image.references`, `image.batch`,
`jobs.history`, `jobs.retry`, `jobs.sync`, `config`, `models.capabilities`.

Выбери config/data по намерению пользователя. Обычная работа может использовать
его существующую историю; новый data-root для каждой генерации не требуется.
Если выбор неоднозначен, уточни нужную историю. Явные `--config` и `--data-dir`
ставятся **перед доменом**, например:

```text
aimedia --config /path/to/settings.toml --data-dir /path/to/history jobs costs --json
```

`/path/to/...`, `<model-id>` и `<job-id>` здесь и ниже — заменяемые placeholders,
не готовые файлы/ID. Относительные пути разрешаются от текущей рабочей папки.
Smoke-проверки направляй только в собственные изолированные config/data roots,
не в пользовательскую историю. Полный test suite перед каждым изображением не нужен.
Ключ берётся только из environment (`POLZA_API_KEY` или настроенное имя-алиас);
в TOML — лишь ссылка `polza_api_key_env`. Не передавай секрет в argv, prompt, URL,
TOML, историю или logs. CLI не подхватывает `.env` из cwd автоматически.

## Найди модель или прошлое изображение

**Каталог моделей:** `models list/show`, не `models search`.

```text
aimedia models list --provider polza --json
aimedia models show <model-id> --provider polza --json
```

При поиске по имени/семейству/статусу фильтруй `data` JSON на стороне host/агента
по `id`, `name`, `family`, `status`, `providers`. У `models list` нет `--family`
или текстового search. Из `models show` проверь effective возможности выбранного
provider: текстовый вход, references и их число/форматы, нужные параметры и
сочетания. Выбирай модель явно. Experimental требует осознанного
`--allow-experimental`, не автоматического fallback.

**Каталог изображений — локальная история Jobs:**

```text
aimedia jobs recent --limit 20 --json
aimedia jobs search "character" --status completed --limit 20 --json
aimedia jobs show <job-id> --json
```

`jobs search` — лексический DB-only FTS5 по сохранённым prompts, путям/именам,
референсам, hashes и metadata результатов. Это не visual similarity, OCR,
семантический поиск или обход файловой системы. Слово для поиска замени на
характерный термин своего проекта; отсутствие совпадения не доказывает отсутствие
похожей картинки. Из `show` бери фактические artifact/managed input пути,
проверяй наличие и открывай нужное изображение; не выдумывай файл по имени Job.

## Генерация: короткий рабочий цикл

1. Сформулируй цель, prompt и критерии результата; выбери модель, её настройки,
   реальные входные файлы и место сохранения. Brief из другого навыка, включая
   `visual-story-director`, — материал, **не** разрешение потратить деньги.
2. До первого paid вызова получи явное согласие на выбранный план: максимум
   запросов и расходов по валюте. Резервируй верхние оценки **всего batch**,
   включая inflight, прошлые неизвестные исходы в согласованном бюджете и отдельные
   deliberate retries. Если верхняя оценка неизвестна — сначала согласуй её,
   не обещай жёсткий лимит от CLI. Каталожный тариф не гарантирует actual billing.
3. Проверь UTF-8 prompt-файлы и реальные images. `--prompt` и `--prompt-file`
   повторяются и объединяются в общем порядке argv с двумя переводами строк;
   `--image` повторяется, порядок сохраняется. Нужна поддержка выбранной модели.
4. Только после согласия выполни один запрос. Пример ниже **платный, не smoke**;
   все файлы должны реально существовать. `base.md`, `scene.md`, images и
   `results` — примеры путей пользователя, не ресурсы навыка:

```text
aimedia image generate --model <model-id> --allow-experimental --prompt-file base.md --prompt "Keep the character identity" --prompt-file scene.md --image character.png --image style.webp --out results --format webp --keep-original --json
```

Добавляй `--allow-experimental` только при выбранной experimental модели;
разрешение, пропорции и остальные controls выбирай из её текущего `models show`.
Явный `--out` **должен уже существовать** и быть доступным. Без `--out` используется
managed outputs выбранного data-root. Запись no-clobber: старые файлы не
перезаписываются, фактическое имя может иметь suffix. `--format` — конечный
локальный `png`/`jpeg`/`webp` (`jpg` — alias), не native формат модели.
`--keep-original` сохраняет provider-original отдельно от final.

Один запрос/Job создаёт **одно** выходное изображение; для нескольких независимых
Jobs используй `image batch`. Каждый positional prompt-файл batch — отдельный
Job, а несколько `--prompt-file` в generate — один compiled prompt.
Проверь `image batch --help`; согласуй бюджет всех items, а не только concurrency.

5. Проверь exit code и JSON (`ok`, Job, artifacts, cost/error); в JSON mode stdout
   — один документ. Через `jobs show` найди реально сохранённый **final**, открой
   его и оцени по задаче. Не называй generation или reference принятыми до
   просмотра и фактического решения пользователя. Сообщи Job ID, actual path,
   известную стоимость/валюту или unknown, недостатки и следующий шаг.

## Создание референсов

Это обычный **платный `image generate`**, не команда `reference generate`.
Подготовь ясное эталонное задание: персонаж — внешность, одежда, полный рост/ракурс
и нейтральная поза; стиль — палитра, линия, материал и свет на понятном мотиве;
предмет — форма, материал, масштаб и нужные виды; локация — геометрия, ориентиры,
свет и ракурс. Не смешивай эталон с большим сюжетным эпизодом.

После согласия и generation проверь реально полученный final, доступность файла
и соответствие brief, покажи пользователю. Только после его approval передай
**фактический путь этого файла** через `--image` в следующий отдельно согласованный
Job. При нескольких референсах назови роли и порядок. Если файл отсутствует или
не просмотрен — так и скажи; карточка/ID не заменяет утверждённое изображение.

## Расходы и безопасное продолжение

```text
aimedia jobs costs --json
aimedia jobs costs --today --json
aimedia jobs costs --month --json
```

Фильтры периода относятся к **UTC-времени создания Jobs**; без них — вся история
**выбранного data-root**, не все расходы на машине. Суммы actual из истории,
включая priced failed Jobs, — не баланс аккаунта и не каталожная оценка.
Разбирай денежные строки через Decimal, группируй валюты отдельно без FX/float.
Отдельно показывай known priced, known zero и unknown Jobs; unknown не превращай
в ноль и не заменяй тарифом. Для конкретной попытки используй `jobs show`.

При timeout/Ctrl+C ожидание прекращается, но remote execution не отменяется.
При неопределённом исходе submit останови новые paid вызовы, сохрани резерв;
никакого автоматического повторного submit или смены модели.
`jobs sync <job-id>` — GET-only status/download recovery **известного сохранённого
remote ref**, не новый POST. Без ref sync не угадывает execution. Это сетевой
вызов, не offline-проверка; используй адресно по согласованной задаче.
`jobs retry <job-id>` создаёт **новый платный Job**, старый не меняет: требуется
отдельное deliberate согласие и резерв бюджета, даже если предыдущий failed.
Не выводи разрешение на retry из слова «sync» или из наличия готового prompt.
