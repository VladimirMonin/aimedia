# README

**Итоговая версия текущего этапа: 1.2.0, зафиксирована 2026-10-02.**
Сохранена подробная редакция инструкций. Результаты и границы проверки описаны
в [приёмке](docs/acceptance.md).

**visual-story-director** готовит визуальную историю, страницы комикса, промпты
и сценарии озвучки. Работает с обычным файловым агентом без image/TTS-инструментов.
Вход и режимы описаны в [SKILL.md](SKILL.md). Основные материалы на русском;
язык ответа и промпта следует запросу, видимые реплики сохраняются отдельно.

## Использование

Передай агенту путь к SKILL.md и свою задачу: «Сначала только историю», «Промпт
на страницу 2», «Продолжи выбранный проект», «Весь пакет, решения выбери сам».
Для установки копируется **только папка visual-story-director** в поддерживаемый
host каталог навыков. Глобальная установка не выполняется этим пакетом.
Для Codex обычно используется пользовательский каталог skills; для другого host
следуй его документации. Здесь проверялось явное чтение навыка агентом, а не
автоматическое обнаружение во всех продуктах. Метаданные клиента не обязательны.

Полный JSON задаётся [контрактом](references/handoff-contract.md), но в разговоре
достаточно обычного Markdown. Начать можно без идеи, стиля и картинок.
Готовые пользовательские решения имеют приоритет. Установочный каталог не является
папкой для пользовательских проектов или производственных файлов.

Длина руководств определяется содержанием. Повторяющиеся баннеры «читать целиком»
не используются. Документ длиннее 1000 строк получает совет улучшить навигацию,
а не блокировку выпуска. Детальность руководства и объём ответа по узкому запросу
оцениваются отдельно.

## Проверки

Творческий режим не имеет программных зависимостей. check_bundle.py использует
стандартную библиотеку Python 3.10+. Для полной JSON Schema проверки требуется
jsonschema 4.26.0: [requirements-checks.txt](requirements-checks.txt). Если зависимости
нет, установи её в отдельное окружение проверок; отсутствие даёт exit 2, не успех.

Из корня пакета команды выполняются отдельно:

```bash
python -B scripts/check_bundle.py --root . --json
```

```bash
python -B scripts/validate_contract.py --input tests/fixtures/valid/complete-package.json --json
```

```bash
python -B -m unittest discover -s tests -v
```

Для сверки old_value локальной правки добавь --baseline:

```bash
python -B scripts/validate_contract.py --input examples/targeted-revision/after-line.json --baseline examples/targeted-revision/before.json --json
```

Без baseline проверяются собственная базовая редакция и связи; сравнение старого
значения с прошлым документом явно отмечается пропущенным. В ContextDelta старое
значение сравнивается с включённым ProjectContext. Коды 0/1/2: пройдено / дефект
входа / сбой исполнения. `-B` отключает побочные Python bytecode-кеши.

## Состав и ограничения

В пакете одна точка входа, 18 руководств, 10 заполненных шаблонов, шесть стилевых
и четыре компоновочных пресета, три схемы, пять законченных авторских примеров,
офлайн-валидаторы и отрицательные тесты. [Матрица E01–E32](evals/evals.json) —
спецификация испытаний, а не обещание 32 независимых прогонов. Дополнительные
[E33–E37](evals/comprehension-cases.json) проверяют понимание и сохранение масштаба.

Авторские examples не выдаются за результаты агента. Реальные прогоны сохраняются
снаружи пакета; текущая степень проверки — в [приёмке](docs/acceptance.md).
Происхождение — в [source-map](docs/source-map.md), [решениях](docs/implementation-decisions.md)
и [upstream-lock](provenance/upstream-lock.json). Доноры не являются зависимостями.

Редакция 1.1 добавляет [процесс решений и возвратов](references/development-process.md)
и отдельную [проверку понимания зрителем](references/viewer-comprehension.md).
Глубина зависит от задачи; единая норма страниц и обязательная учебная структура
не вводятся. Самопроверка постановки не заменяет чтение реальным человеком.

Редакция 1.2 уточняет существующие критерии после диалогового пилота: знания
и ожидаемый эффект для зрителя, качественные причинные связи, понятность общих
формулировок и необходимость текста. Диалог обсуждает конкретные решения;
учебная ясность и художественный эффект проверяются раздельно. Фиксированных
вопросников и новых обязательных производственных этапов не добавлено.

Формальная проверка текста детерминирована. Интерес истории, плотность текста,
композиция и смысл оцениваются редакторски. Наличие слов в промпте не доказывает
качество будущего изображения. Координаты, шрифт, идентичность и точное исполнение
image-моделью не гарантируются. Изображения, звук и видео этим навыком не создаются.
