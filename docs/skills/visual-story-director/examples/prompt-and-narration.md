# prompt-and-narration

**Авторские примеры формы выдачи.** Имена и предметы не являются каноном новых
проектов. Это творческие задания, без API-параметров и запуска инструментов.

## Готовый промпт одной сцены

Вход: карточка героя реально приложена как identity; текстовая карточка стиля —
как style. Эти условия проверяются до выдачи, не возникают от слов в промпте.

```text
Одна одиночная иллюстрация 16:9, без сетки последовательных панелей.
Используй приложенный identity-референс для внешности героя и карточку style
для рисованного 2D-стиля. Новая поза: герой остановился у двери и показывает
на закрытый засов. Зелёная лампа и засов крупно видны одновременно справа;
герой слева смотрит именно на засов. Главный акцент — различие двух признаков.
Точная подпись возле лампы: «Питание есть». Возле засова: «Замок закрыт».
Это подписи без хвостиков. Не показывай открытый проход и следующее действие.
```

Если identity отсутствует, задание становится текстовым draft с описанной
внешностью либо needs_input, без утверждения о приложении. По «только промпт»
выводится само готовое задание, без объяснения всего процесса разработки.

## Референс предмета

```text
Один сравнительный лист трёх состояний одного контейнера, вид спереди.
Постоянный дизайн: прямоугольный жёлтый корпус, ручка сверху, три гнезда,
одна крупная этикетка. Простой рисованный 2D-стиль, плоские цвета, ясный контур.
A: три колбы и ошибочная надпись «ОБРАЗЦЫЫ».
B: надпись «ОБРАЗЦЫ», среднее гнездо пусто, две другие колбы на месте.
C: тот же B, добавлена только колба в среднее гнездо; остальные части сохранены.
Служебные A/B/C находятся вне контейнеров. Все три состояния полностью видны.
Без персонажей и без сюжетного действия.
```

Для адресной правки передаётся только нужная пара исходник/целевое изменение,
а не все состояния листа без выбора. Пример —
[предмет и review](prop-states-and-review.md).

## JSON как запись творческого задания

```json
{
  "image_request": "one single illustration, no panel grid",
  "aspect_ratio": "16:9",
  "action": "Герой указывает на закрытый засов рядом с зелёной лампой",
  "visible_text": ["Питание есть", "Замок закрыт"],
  "text_placement": "Первая подпись возле лампы, вторая возле засова, без хвостиков",
  "visual_style": "Рисованный 2D, ясный контур и крупные плоские цвета",
  "focus": "Различие двух одновременно видимых признаков",
  "constraints": ["Не показывать открытый проход", "Не рисовать служебные поля"]
}
```

Это произвольная запись prompt brief, не объект схемы preproduction-package и
не API request. Исполнитель получает её как творческое задание. Для полного
структурированного экспорта используется существующий контракт без новых enum.

## Производный рассказ от третьего лица

Исходные события: герой видит зелёную лампу, тянет ручку, дверь закрыта;
замечает засов, открывает его, проходит. Реплика на изображении первой попытки:
«Зелёный! Можно идти». Она остаётся в комиксе при адаптации озвучки.

| Привязка | Новый narration-текст |
| --- | --- |
| Первая попытка | «Увидев зелёную лампу, герой решил, что дверь уже открыта. Он потянул ручку, но дверь не сдвинулась». |
| Обнаружение | «Лампа показывала питание. Сам замок оставался закрытым: это было видно по засову». |
| Следующая попытка | «Герой открыл засов и снова потянул ручку. На этот раз он смог пройти». |

Новые строки получают собственные ID и narration kind при структурированном
экспорте. Старый dialogue Line не заменяется и его speaker не переименовывается.
Запрос на такую адаптацию разрешает draft, не выдуманное утверждение новых строк.
В варианте «один диктор читает все роли дословно» используются исходные реплики
с прежними персонажными speaker_id, без этого пересказа.

Проверка: narration следует изображению, не сообщает заранее об открывании;
объяснение относится к установленному правилу мира; немая версия проверяется
отдельно с её собственными подписями. Без записи звука точного timing нет.
