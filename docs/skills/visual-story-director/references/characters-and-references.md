# characters-and-references

**Персонаж — участник действия, а не только внешность.** Карточка содержит ID,
вид сущности, роль, характер, мотивацию по необходимости, манеру речи, отличительные
признаки и неприкосновенные решения. Человек, животное и гусеничный робот имеют
разные признаки; не добавляй роботу волосы, пол и пальцы из человеческого шаблона.

У решения два независимых атрибута: происхождение (`user`, `source`, `agent`)
и согласование (`unknown`, `proposed`, `approved`, `rejected`). Выведенный из
источника признак не становится автоматически approved. Отдельно отметь известные
незаполненные параметры; предлагай только нужные сценам дополнения.

Референсы связываются ролями `character_identity`, `style`, `location`, `prop`,
`composition`, `previous_frame`. ID разрешает host; `asset://` не является
универсальным рабочим протоколом. Доступность, просмотр и утверждение проверяются
раздельно. При `available` укажи реальный locator и свидетельство проверки host;
при `inspected` — основание просмотра. `missing` не запрещает текстовый сценарий.

Identity-референс фиксирует силуэт, лицо и отличительные признаки; новая панель
может менять позу, эмоцию и ракурс. Composition-референс не импортирует чужих героев.
При готовом утверждённом образе не переописывай его произвольно.

Если образов нет, напиши одно задание на основной вид. Дополнительные виды назначь
по сценам: лицо для эмоций, боковой/задний вид для нужных действий, деталь для
сюжетного признака. По запросу листа 16:9 задаются фронт, профиль, спина и детали,
но для каждого героя отдельная единица. Сам навык изображений не создаёт.
В character_reference нет реплик сюжета и обещания приложенного отсутствующего файла.
