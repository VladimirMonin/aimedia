# prompt-writing

**Один промпт — одна целевая единица.** Типы: `comic_page`, `single_panel`,
`character_reference`. Разные страницы и разные форматы имеют отдельные задания.
Промпт не является job, seed, quality-параметром или историей запусков.

Для comic_page собери: тип и ratio; число панелей и полосы; порядок чтения;
по каждой панели действие, участники, камера, окружение, текст и говорящий;
свет, важные ограничения и роли референсов. Реплики впиши дословно, подписи
отдели от облачков. Перечень visible_lines содержит ID, text и speaker_id,
совпадает с постановкой и реально продублирован в prompt text при `in_image`.
Проверка подстроки ловит потерю, но не доказывает правильную картинку.

`external_lettering`: в prompt text закажи свободные зоны и отсутствие нарисованных
букв; точный lettering plan остаётся в visible_lines и text_zones для внешней
вёрстки. Не вставляй точные строки в задание «без текста» так, чтобы они оказались
случайно отрисованы. Сам навык текст кодом не накладывает.

`self_contained` содержит достаточные стиль, внешность при текстовом образе,
постановку и необходимые ограничения. Реальные изображения могут прилагаться
с объявленными ролями. `with_context` перечисляет required_context: какой
документ или изображение нужно и как его разрешает host. При недоступном контексте
готовность needs_input либо честный draft без обещания приложения.

Не заменяй описание стиля непрозрачным ID. Не повторяй дизайн утверждённого героя,
если он передаётся identity-референсом. Не предполагается, что API понимает Markdown.
Служебные ID, названия панелей и режиссёрские команды не являются надписями.

Для правки: сохранить → изменить только указанный объект → неприкосновенные
свойства → ожидаемый результат. Содержательные запреты не требуют API negative_prompt.
По «только промпт» выдай лишь копируемый текст; предупреди о критической нехватке
в самом задании кратко, если автономность без неё невозможна.
