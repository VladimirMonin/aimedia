# story-development

**Выбери структуру по задаче.** Для решения проблемы: цель → попытка → результат →
препятствие → решение. Для объяснения: вопрос → опыт → сравнение → вывод. Для
инструкции: исходное состояние → действия → проверка. Для шутки: ожидание →
нарушение → реакция. Для атмосферы: ситуация → изменение восприятия → итог.
У готового рассказа сохраняй авторскую структуру, включая нелинейность.

Каждый `StoryBeat` содержит функцию, видимое событие, состояние до/после и
смысловую связь с предыдущим. Функция может быть паузой или наблюдением;
не требуется конфликт в каждой панели. Пример: робот сравнивает табличку
с растерянным посетителем и разворачивает стрелку к входу. «Робот всё понял»
без наблюдаемого действия не годится для постановки.

Объясняй через работу героев. Для мастерской подходит табличка мастерской,
а случайный зонтик уводит сюжет, если он не нужен цели. Дай зрителю заметить
разницу до реплики с выводом. Используй молчаливые реакции и визуальные результаты.

Для абстракций составь небольшую карту: понятие → образ → граница аналогии.
Повторяющийся символ сохраняет значение; финал не обязан собрать все символы.
Не навязывай наставника, рост героя и тёплый свет независимо от жанра.

Объём выводи из существенных изменений и необходимых для их понимания опор,
используя [процесс разработки](development-process.md). Тема, эпизод, страница и
панель не обязаны совпадать. При конфликте предложи сокращение охвата,
другой выпуск или изменение глубины. История заканчивает выбранную задачу;
открытая линия допустима, если это авторское решение, а не обязательный крючок.
Для story-only остановись здесь: бриф и история без полного комплекта промптов.
